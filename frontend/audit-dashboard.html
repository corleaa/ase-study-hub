CRITIC JS logic în inline <script> — imposibil de testat izolat
Tot routing-ul aplicației (renderPage()), state management (saveState()), auth, și PDF export sunt în 2 blocuri <script> inline din index.html (~1369 linii total). Un AI repair bot nu poate modifica aceste funcții fără riscul de a rupe navigația întreagă.
Locație: index.html liniile 6246–7399 și 7401–7615 | Impact: ÎNTREG UI-UL
Risc pentru automatizare: Orice modificare a inline script poate rupe renderPage(), saveState(), auth flow sau PDF export simultan.
Recomandare: Extrage renderPage() și saveState() în js/app-core.js (necesită review manual, nu automat).
CRITIC 8 fișiere JS dead code (module system abandonat)

RIDICAT index.html inline scripts — routing și auth
Două blocuri <script> inline conțin ~1369 linii de logică critică:
  • renderPage() — tot routing-ul aplicației
  • saveState() / window.state — state management global
  • unlock() / openAuthModal() — auth flow
  • exportProgressPDF() — generare PDF în popup
  • showToast() / initTheme() — utility functions globale

Regulă pentru AI agents: NU modifica aceste funcții automat. Orice schimbare în inline script poate rupe întreaga aplicație simultan.
MEDIU subject-page.js (2002 ln) — HTML generat dinamic
Aproape tot HTML-ul pentru pagina de materie e generat ca string în JS. Dacă adaugi o clasă CSS nouă, trebuie să o adaugi și în stringul JS. Verifică cu grep "class-name" js/subject-page.js înainte de a asuma că un selector CSS e vizibil.
MEDIU CSS cascade — override-uri V1.3/V7/V8/GLOBAL
css/app.css a fost construit incremental. Secțiunile mai noi pot override-ui selectori definiți anterior. Ordinea de verificare pentru un selector:
  1. Găsește prima definiție în secțiunea relevantă
  2. Caută override-uri în secțiunile V1.3, V7, V8
  3. Verifică UPDATED GLOBAL STYLES (ultima secțiune, ~ln5405) — are override-uri globale
